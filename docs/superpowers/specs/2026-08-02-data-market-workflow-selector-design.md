# 数据市场主题域标签与流程定义选择器设计

## 目标

本次仅调整数据市场管理后台的两处交互：

1. 业务主题域新增、编辑弹窗中的“上级主题域”标签保持单行显示。
2. 流程配置页不再要求管理员手工填写流程定义 Key 和名称，改为从 BPM 已启用流程中选择。

不修改数据市场后端接口、数据库结构、BPM 流程模型或审批执行逻辑。

## 主题域表单

- 将主题域弹窗表单的统一标签宽度从 `90px` 调整为 `110px`。
- “名称”“编码”“上级主题域”“排序”“状态”“说明”继续共用同一标签宽度，保证输入控件左侧对齐。
- 不通过强制截断、缩小字号或隐藏文字解决换行问题。

## 流程定义选择器

### 数据来源

- 页面加载时调用现有 `GET /bpm/process-definition/simple-list`。
- 该接口仅返回未挂起流程，并提供 `id`、`name`、`key`，符合配置下拉框用途。
- 同一流程 Key 可能因多次部署出现多条活动版本；前端按 Key 去重。配置保存的是 Key，版本差异不进入数据市场映射。
- 不新增数据市场后端代理接口，也不引入新的 BPM 权限或数据库字段。

### 页面交互

- 将“流程定义 Key”和“流程定义名称”两个文本输入框合并为一个“流程定义”可搜索下拉框。
- 选项展示为 `流程名称（流程 Key）`，选项值使用流程 Key。
- 选择流程后，同时更新表单中的 `processDefinitionKey` 和 `processDefinitionName`，继续按现有 `WorkflowConfigVO` 保存。
- 切换申请类型时，先读取该类型现有配置，再根据 Key 恢复下拉框选中项。
- 加载状态期间禁用选择器，避免列表未就绪时误操作。

### 历史配置兼容

- 如果当前保存的 Key 不在已启用流程列表中，增加一个禁用的临时选项。
- 临时选项展示现有名称和 Key，并标记“已停用或不可见”。
- 用户可以保留当前配置，也可以改选一个已启用流程；页面不会因列表缺项而把原配置清空。

### 异常与空状态

- BPM 流程列表加载失败时展示明确错误消息，保留已读取的数据市场流程配置。
- 无可用流程时使用下拉框空状态提示，不退回手工输入 Key。
- 保存前继续校验 `processDefinitionKey` 必填；校验触发方式改为 `change`。

## 测试与验收

- 页面测试覆盖 BPM 简单流程列表加载、流程选择后 Key/名称同步，以及历史缺失流程的禁用回显。
- 页面测试覆盖主题域表单使用足够的统一标签宽度。
- 运行数据市场完整单元测试、TypeScript 类型检查、Prettier 检查和本地生产构建。
- 在真实管理后台验证主题域标签单行显示、流程下拉搜索、切换申请类型和历史配置回显。

## 验收标准

- “上级主题域”在正常桌面弹窗宽度下不换行。
- 管理员无需知道流程定义 Key，可按名称或 Key 搜索并选择流程。
- 保存请求仍携带正确的 `processDefinitionKey`、`processDefinitionName` 和状态。
- 已停用或不可见的历史流程配置不会静默丢失。
