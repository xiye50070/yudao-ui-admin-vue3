# 数据市场管理端引用选择器交互设计

日期：2026-08-02  
状态：已确认

## 1. 背景

数据市场管理端的业务主题域、来源系统和数据集表单当前直接要求用户填写数据库 ID：

- 业务主题域填写“上级 ID”；
- 来源系统填写“负责人 ID”和“负责部门 ID”。
- 数据集填写“来源系统 ID”和“主题域 ID”。

业务用户无法通过裸 ID 判断目标对象，也无法识别多层级主题域、部门以及人员所属关系。此次改造把这些技术字段替换为面向业务名称的选择控件，前端展示名称和层级，提交时仍沿用现有数值 ID 字段，避免改变后端数据模型和接口契约。

## 2. 已确认的产品决策

1. 业务主题域的上级选择采用树形选择方案，顶级主题域映射为 `parentId = 0`。
2. 来源系统的负责部门采用多层级部门级联选择。
3. 来源系统的负责人采用“独立部门级联筛选 + 用户搜索选择”的组合方式。
4. 负责人查找用的部门级联仅用于缩小人员候选范围，与来源系统的“负责部门”字段完全独立：两者互不赋值、互不校验、互不清空。
5. 前端只展示业务名称和层级，向接口提交时继续使用 `parentId`、`ownerDeptId`、`ownerUserId`。
6. 数据集新增、编辑时通过名称选择来源系统，通过层级选择主题域，接口继续提交 `sourceSystemId` 和 `subjectDomainId`。

## 3. 范围

### 3.1 本次包含

- 业务主题域新增、编辑弹窗中的上级主题域选择器；
- 来源系统新增、编辑弹窗中的负责部门级联选择器；
- 来源系统新增、编辑弹窗中的负责人部门筛选和用户搜索选择器；
- 来源系统列表中的负责人、负责部门名称展示；
- 数据集新增、编辑抽屉中的来源系统和主题域选择器；
- 数据集发布弹窗中的主题域选择器；
- 数据集列表中的来源系统、主题域名称展示；
- 新增纯函数和单元测试，覆盖树构建、循环规避、部门后代计算和人员筛选；
- 新增、编辑、清空、回显、加载失败等基本交互状态。

### 3.2 本次不包含

- 不修改数据库表结构；
- 不改变来源系统保存接口的请求字段；
- 不要求负责人必须隶属于负责部门；
- 不自动根据负责人填写负责部门，也不根据负责部门限制负责人；
- 不在本次范围内改造标签、ACL 主体等其他 ID 输入项。

## 4. 交互设计

### 4.1 业务主题域：上级主题域

- 将“上级 ID”改名为“上级主题域”。
- 使用可搜索、可展开的树形选择器，节点显示主题域名称。
- 增加显式根节点“顶级主题域”，选择后提交 `parentId = 0`。
- 允许选择任意层级节点，不强制只能选择叶子节点。
- 编辑主题域时，从候选树中移除当前主题域及其全部后代，防止形成父子循环。
- 新增时默认选择“顶级主题域”；编辑时按保存的 `parentId` 回显。
- 主题域列表数据继续由现有 `getSubjectDomainList` 接口提供。

### 4.2 来源系统：负责部门

- 将“负责部门 ID”改名为“负责部门”。
- 使用 Element Plus 级联选择器展示完整部门层级。
- 支持展开多级部门、输入名称过滤、清空选择。
- 任意层级部门均可选择；通过 `emitPath: false` 仅将末级选中节点 ID 写入 `ownerDeptId`。
- 部门数据来自现有 `/system/dept/simple-list`，仅展示启用部门。
- 编辑时根据 `ownerDeptId` 回显完整路径，但接口仍收到单个部门 ID。

### 4.3 来源系统：负责人

负责人表单项由两个相邻控件组成：

1. “按部门筛选”级联选择器：
   - 仅作为查找人员的 UI 筛选条件，不进入保存请求；
   - 展示完整部门层级，支持搜索和清空；
   - 选择某部门后，候选人员包含该部门及其所有下级部门中的启用用户；
   - 未选择部门时展示全部启用用户。
2. “请选择负责人”可搜索下拉框：
   - 支持按用户昵称、登录账号和部门名称搜索；
   - 选项主文案显示用户昵称，辅助显示登录账号和所属部门；
   - 选中后仅把用户 ID 写入 `ownerUserId`。

负责人部门筛选值采用独立的页面状态，例如 `ownerLookupDeptId`，不得混入 `SourceSystemVO` 或保存请求。修改该筛选条件时，如果已选负责人不在新候选范围内，则保留负责人值并在候选列表中保留该人员，避免纯查找动作意外修改业务数据；用户主动清空或改选负责人时才改变 `ownerUserId`。

### 4.4 两个部门选择器的独立性

- “负责部门”表达来源系统的责任组织，保存到 `ownerDeptId`。
- “按部门筛选”表达负责人查找范围，只存在于当前弹窗状态。
- 选择、清空任一控件都不会修改另一个控件。
- 负责人所属部门与负责部门不一致时允许保存，不显示阻断性校验。

### 4.5 列表展示

- 将“负责人 ID”列改为“负责人”，通过用户字典展示昵称。
- 将“负责部门 ID”列改为“负责部门”，通过部门字典展示名称。
- 当前精简接口中无法找到的历史引用统一显示“已停用或不可见”，不把裸 ID 暴露给业务用户。

### 4.6 数据集：来源系统和主题域

- 将数据集新增、编辑抽屉中的来源系统数字输入框改为可搜索下拉框。
- 来源系统选项显示“系统名称（系统编码）”，选中后仅将数值 ID 写入 `sourceSystemId`。
- 来源系统候选通过现有来源系统分页接口加载；打开下拉框时加载首批候选，输入名称或编码时远程搜索，编辑回显时保留当前来源系统选项。
- 将“主题域 ID”改名为“业务主题域”，复用多层级主题域树，支持展开和名称搜索。
- 数据集必须选择实际主题域，不提供“顶级主题域”作为业务数据集归属选项；通过 `emitPath: false` 仅将选中节点 ID 写入 `subjectDomainId`。
- 发布数据集弹窗中的“主题域 ID”同步使用同一主题域选择器，避免同一业务字段在不同流程中出现两套交互。
- 数据集列表优先使用接口已有的 `sourceSystemName`、`subjectDomainName` 展示业务名称；缺失时再用本地字典解析，仍无法解析则显示“已停用或不可见”。
- 新增、编辑和发布保存接口保持现有请求结构，不提交名称、路径或选择器内部状态。

## 5. 数据与接口

### 5.1 复用接口

- `GET /data-market/management/subject-domains`
- `GET /system/dept/simple-list`
- `GET /system/user/simple-list`
- `GET /data-market/management/source-systems`
- 来源系统现有创建、更新接口
- 数据集现有创建、更新、发布接口

用户和部门精简接口当前没有额外的系统管理查询权限要求，登录后的数据市场管理端可用于下拉选项。两者仅返回启用记录，符合新建业务配置的候选范围。

### 5.2 页面状态

- `subjectDomainTree`：主题域树；
- `deptTree`：部门级联树；
- `userList`：全部启用用户；
- `ownerLookupDeptId`：负责人查找用的部门节点 ID，仅在前端存在；
- `filteredOwnerUsers`：部门后代范围与关键字条件共同作用后的用户候选；
- `userNameMap`、`deptNameMap`：列表名称解析字典。
- `sourceSystemOptions`：来源系统搜索结果及编辑回显选项；
- `datasetSubjectDomainTree`：去掉虚拟顶级节点的数据集主题域树。

## 6. 异常与边界处理

- 打开新增、编辑弹窗前确保引用数据已加载；加载过程中显示表单 loading。
- 引用数据加载失败时提示“人员或部门数据加载失败，请重试”，禁用相关选择器，但不把空候选误认为真实数据。
- 编辑记录引用已停用人员或部门时，保留原 ID，不在用户未主动修改的情况下清空；界面展示“已停用或不可见”。
- 空部门、空用户列表均提供明确空状态。
- 表单关闭或打开新增记录时重置 `ownerLookupDeptId` 和搜索关键字，避免把上一次查找条件带入下一次操作。
- 数据集引用候选加载失败时保留已经回显的来源系统或主题域值，不因选项请求失败修改表单数据。

## 7. 实现结构

为避免把层级与筛选逻辑堆积在页面组件内，新增数据市场引用选择器辅助模块，提供以下纯函数：

- 构建主题域父级候选树，并排除编辑节点分支；
- 构建部门级联树；
- 计算某部门节点及其全部后代 ID；
- 根据部门范围和搜索关键字过滤用户；
- 根据 ID 解析负责人、部门展示名称。
- 构造来源系统显示标签，并合并远程搜索结果与编辑回显选项。

页面组件只负责加载数据、维护表单状态、渲染控件和调用现有保存接口。

## 8. 验收标准

1. 新建主题域时可通过名称和层级选择上级，顶级主题域保存为 `parentId = 0`。
2. 编辑主题域时无法把自身或后代设为上级。
3. 负责部门可通过多层级级联选择并正确回显，提交值是单个数值 ID。
4. 负责人可先用独立部门级联缩小范围，再按姓名、账号或部门搜索。
5. 负责人筛选部门与负责部门互不影响。
6. 来源系统列表不再以裸 ID 作为主要展示内容。
7. 新增、编辑数据集时可按名称或编码选择来源系统，并按层级选择主题域。
8. 发布数据集时通过同一主题域树选择主题域，数据集列表展示来源系统和主题域名称。
9. 保存接口请求体没有 UI 筛选字段或级联路径，后端接口契约不变。
10. 新增单元测试通过，数据市场 TypeScript 检查与管理端构建通过。
